# Analytics: Rollups, Geography, Scheduled Jobs and Query Services — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the raw click stream into numbers a dashboard can read instantly: daily totals and unique counts per link, breakdowns by country, city, referrer, device, operating system, browser, UTM and target platform, optional geographic resolution, and the scheduled jobs that keep all of it honest and bounded.

**Architecture:** `record_click` keeps writing one `ClickEvent` and now also upserts two rollup tables in the same transaction, so the dashboard never scans raw events. `apps/analytics/geo.py` wraps an optional GeoLite2 database: when no file is configured the fields stay blank and nothing fails. `apps/analytics/queries.py` is the only module the dashboard will import, returning plain dictionaries. A `supercronic` process in the worker container enqueues the periodic jobs; cron only triggers, the worker does the work.

**Tech Stack:** Django 6.1, `django.tasks`, PostgreSQL upserts via `bulk_create(update_conflicts=True)`, `geoip2` (new, optional at runtime), `supercronic` in the worker image.

**Spec:** `docs/superpowers/specs/2026-09-17-short-design.md` sections 3 (`DailyLinkStat`, `DailyLinkBreakdown`), 5 (the task table and scheduling) and 8 (retention, salt rotation).

## Global Constraints

- English everywhere; commits `GH-<issue>-<type>: description` on branch `GH-<issue>`; no AI attribution.
- No hostnames, IPs or secrets; new env vars go into `.env.example` (a test enforces coverage).
- Geographic resolution is optional: with no `GEOIP_PATH` configured the app must run normally and country and city stay blank. The GeoLite2 database is never committed.
- Rollups are upserts and must be safe to recompute: running `rebuild_daily_stats` for a day must produce exactly what the incremental path produced.
- A unique click is one `ip_hash` plus `user_agent` per link per day, as the spec defines it.
- Scheduled jobs only enqueue; the worker executes. Nothing schedules itself inside the web process.
- Retention: raw events older than `CLICK_EVENT_RETENTION_DAYS` are deleted in batches; rollups are kept.
- Query functions take a workspace (and optionally a link) and never accept raw SQL fragments or ordering from the caller.
- Tests: `uv run pytest` 0 warnings; ruff, pre-commit and `makemigrations --check` clean. No test reads a GeoLite2 file or reaches the network.

- [ ] **Step 3: Models**

Add to `apps/analytics/models.py`:
```python
class Dimension(models.TextChoices):
    COUNTRY = "country", "Country"
    CITY = "city", "City"
    REFERRER = "referrer", "Referrer"
    DEVICE = "device", "Device"
    OS = "os", "Operating system"
    BROWSER = "browser", "Browser"
    UTM_SOURCE = "utm_source", "UTM source"
    UTM_MEDIUM = "utm_medium", "UTM medium"
    UTM_CAMPAIGN = "utm_campaign", "UTM campaign"
    TARGET_PLATFORM = "target_platform", "Target platform"


class DailyLinkStat(models.Model):
    """One row per link per day. The dashboard reads these, never the raw events."""

    link = models.ForeignKey("links.Link", on_delete=models.CASCADE, related_name="daily_stats")
    workspace = models.ForeignKey("workspaces.Workspace", on_delete=models.CASCADE, related_name="daily_stats")
    date = models.DateField()
    clicks = models.PositiveIntegerField(default=0)
    unique_clicks = models.PositiveIntegerField(default=0)
    bot_clicks = models.PositiveIntegerField(default=0)

    class Meta:
        ordering = ["-date"]
        constraints = [models.UniqueConstraint(fields=["link", "date"], name="analytics_daily_stat_unique")]
        indexes = [models.Index(fields=["workspace", "-date"])]


class DailyLinkBreakdown(models.Model):
    """One row per link, day, dimension and value."""

    link = models.ForeignKey("links.Link", on_delete=models.CASCADE, related_name="daily_breakdowns")
    workspace = models.ForeignKey("workspaces.Workspace", on_delete=models.CASCADE, related_name="daily_breakdowns")
    date = models.DateField()
    dimension = models.CharField(max_length=20, choices=Dimension.choices)
    value = models.CharField(max_length=255)
    clicks = models.PositiveIntegerField(default=0)

    class Meta:
        ordering = ["-clicks"]
        constraints = [
            models.UniqueConstraint(
                fields=["link", "date", "dimension", "value"], name="analytics_daily_breakdown_unique"
            )
        ]
        indexes = [models.Index(fields=["workspace", "date", "dimension"])]
```
`ClickEvent` gains nothing; it already carries every field the rollups need.

- [ ] **Step 4: `apps/analytics/rollups.py`**

- `local_date(event)` converts `event.occurred_at` into the workspace's timezone and returns the date, falling back to UTC when the timezone is unusable.
- `dimensions_for(event)` returns the non-empty `(dimension, value)` pairs, truncating each value to 255 and mapping `referrer_host` to `Dimension.REFERRER`.
- `is_unique(event, day)` is true when no earlier `ClickEvent` for the same link, day, `ip_hash` and `user_agent` exists. An empty `ip_hash` counts as unique (we cannot tell them apart, and refusing to count them would understate reality); say so in a comment.
- `apply_event(event)` upserts one `DailyLinkStat` row and one `DailyLinkBreakdown` row per dimension, using `bulk_create(..., update_conflicts=True, update_fields=[...], unique_fields=[...])` with `F` increments where PostgreSQL allows, or a `get_or_create` plus `F` update where it does not. Whichever you choose must be correct under concurrent workers; explain the choice in a comment.
- `rebuild(link, day)` recomputes both tables for that link and day from the raw events, inside one transaction, deleting rows that no longer have events behind them.

- [ ] **Step 5: Call it from `record_click`**

Inside the existing `transaction.atomic()` in `record_click`, after the event is created and the counter incremented, call `rollups.apply_event(event)`. A rollup failure must not lose the event: wrap the call so an exception is logged and swallowed, with a comment saying the nightly rebuild will correct it.

### Task 2: Optional geographic resolution

**Files:**
- Create: `apps/analytics/geo.py`, `tests/analytics/test_geo.py`
- Modify: `apps/analytics/tasks.py`, `apps/redirects/views.py`, `config/settings/base.py`, `.env.example`, `pyproject.toml`, `docs/self-hosting.md`, `.gitignore`

**Interfaces:**
- Produces: `geo.configured() -> bool`; `geo.lookup(ip) -> {"country": str, "city": str}`; setting `GEOIP_PATH` (default empty).

**Design note that the plan must respect:** the task receives a hashed address, not a raw one, so it cannot resolve geography. The lookup therefore happens in the view, next to the hashing, and the result is passed to the task as two short strings. That keeps the raw address in the request and out of the queue, which is the whole point of hashing there.

- [ ] **Step 1: Write the failing tests**

`tests/analytics/test_geo.py`:
- `configured()` is False and `lookup` returns blanks when `GEOIP_PATH` is empty;
- with a fake reader injected, `lookup` returns the country code and city name;
- a lookup failure (unknown address, corrupt database) returns blanks and logs, never raises;
- the reader is opened once and reused, not per call.

Extend `tests/analytics/test_record_click.py` and the redirect view tests: the view passes `country` and `city` through to the task, and they land on the event; with geography unconfigured both stay blank and nothing else changes.

- [ ] **Step 2: Run to verify they fail; then implement**

`apps/analytics/geo.py`:
```python
"""Optional GeoLite2 lookups.

Self-hosters who do not want a MaxMind account simply leave GEOIP_PATH empty: every
lookup returns blanks and nothing else in the product changes.
"""
```

Add `GEOIP_PATH = env("GEOIP_PATH", default="")` and document it in `.env.example` and in `docs/self-hosting.md` (where to download the database, that it is not committed, and that it is optional). Add `*.mmdb` to `.gitignore` if it is not already there.

In `apps/redirects/views._record`, resolve the address before hashing it and pass `country` and `city` to `record_click`; the task stores them on the event and the rollups pick them up through `dimensions_for`.

- [ ] **Step 1: Write the failing tests**

`tests/analytics/test_scheduled_tasks.py`:
- `rebuild_daily_stats` with no argument rebuilds yesterday for every link that has events that day, and corrects tampered rollups; with a date it rebuilds that day;
- `purge_click_events` deletes events older than the retention window in batches, keeps newer ones, keeps rollups, and logs how many it removed;
- `rotate_ip_salt` makes `daily_salt()` return a new value and leaves yesterday's key alone;
- `expire_links` disables links past `expires_at` or `max_clicks`, invalidates their cached payload, and leaves healthy links alone;
- `enqueue_scheduled` enqueues exactly the named task and exits non-zero for an unknown name.

- [ ] **Step 2: Implement**

The four tasks live in `apps/analytics/tasks.py` (`expire_links` too — it is a link concern but a scheduled one, and putting all scheduled work in one place is worth more than app purity; say so in a comment). `purge_click_events` deletes in batches of `ANALYTICS_PURGE_BATCH_SIZE` (default 5000) to avoid a long lock. `expire_links` reuses the links service's invalidation helper rather than touching the cache directly.

`enqueue_scheduled` takes one positional name, looks it up in a dict of allowed tasks, calls `.enqueue()` and prints what it enqueued.

0 0 * * * python manage.py enqueue_scheduled rotate_ip_salt
*/10 * * * * python manage.py enqueue_scheduled expire_links
0 3 * * * python manage.py prune_db_task_results
